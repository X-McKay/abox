## Overview

This plan covers 5 priorities selected from DRAFT_PLAN.md, scoped to what
actually needs building (vs what already exists). Each priority includes
file-level implementation detail, design decisions, and verification criteria.

**Selected priorities:**

| # | Priority | Scope | Why now |
|---|----------|-------|---------|
| P1 | HTTPS credential injection | L (3-4 days) | Security promise is half-true without it |
| P2 | Stabilization release (N2-N7) | S (1-2 days) | Cheap reliability wins; clears debt before features |
| P3 | Snapshot/template fast startup | M (1-2 days) | ~70% exists; wiring unlocks sub-100ms startup |
| P4 | Installation story | M (1-2 days) | `just release` exists but no binary distribution |
| P5 | Runtime controls (--timeout, --ephemeral) | M (1 day) | --memory/--cpus already wired; only 2 flags remain |

## P5: Runtime Controls

`--memory` and `--cpus` are already fully wired from CLI → config → sandbox
→ Cloud Hypervisor (see `run.rs:29,32`, `config.rs:33-50`,
`cloud_hypervisor.rs:200-203`). Only `--timeout` and `--ephemeral` need
implementation.

### --timeout — M

**Design decisions:**
- **Shutdown sequence:** Graceful first (`ch-remote shutdown`), then force
  kill after 10s grace period. Audit log flushes during the graceful window
  via existing console shutdown path.
- **Exit code:** 124, matching GNU `timeout(1)` convention. Scripts can
  distinguish timeout from normal failure.
- **Interaction with --ephemeral:** If both set, timeout triggers cleanup
  just like normal exit.

**Files:**
- `crates/abox-cli/src/commands/run.rs` — add to `RunArgs`
- `crates/abox-core/src/sandbox.rs` — add to `CreateSandboxParams`, implement in `run_sandbox()`

**Implementation:**
1. Add `#[arg(long, help = "Kill sandbox after N seconds")] timeout: Option<u64>` to `RunArgs`.
2. Add `pub timeout_secs: Option<u64>` to `CreateSandboxParams`.
3. Pass through in `run.rs::execute()`.
4. In `run_sandbox()`, wrap the VM exit poll loop:
   ```rust
   let poll_future = async {
       loop {
           // ... existing poll logic (lines ~303-308)
       }
   };

   let exit_code = if let Some(timeout_secs) = params.timeout_secs {
       match tokio::time::timeout(Duration::from_secs(timeout_secs), poll_future).await {
           Ok(code) => code,
           Err(_elapsed) => {
               eprintln!("abox: sandbox '{}' timed out after {}s", task_id, timeout_secs);
               // Graceful shutdown
               self.vm_manager.shutdown(&task_id).await
                   .context("graceful shutdown failed")?;
               // Wait up to 10s for exit
               match tokio::time::timeout(
                   Duration::from_secs(10),
                   /* poll for VmState::Exited */
               ).await {
                   Ok(_) => {},
                   Err(_) => {
                       // Force kill
                       self.vm_manager.force_stop(&task_id).await?;
                   }
               }
               Ok(124) // GNU timeout convention
           }
       }
   } else {
       poll_future.await
   };
   ```
5. The `VmPort` trait may need `shutdown()` and `force_stop()` methods if they
   don't already exist. Check `cloud_hypervisor.rs` — `stop()` exists and
   calls `ch-remote shutdown-vmm`. May need to split into graceful vs forced.

**Verification:**
```bash
abox run --timeout 5 --task timeout-test -- sleep 3600
# Should exit within ~15s with code 124
echo $?  # 124
```

### Task 4: TLS-terminating proxy core — L

This is the largest single task. The current passthrough handler at
`egress_proxy.rs:91-155` is replaced with a MITM proxy.

**Files:**
- Rewrite `crates/abox-proxyd/src/egress_proxy.rs`
- Modify `crates/abox-proxyd/Cargo.toml` — add:
  ```toml
  rustls = "0.23"
  tokio-rustls = "0.26"
  webpki-roots = "0.26"
  ```

**Implementation — new CONNECT handler flow:**

```
Client (in VM)                    Proxy (host)                   Upstream
     |                                |                              |
     |-- CONNECT api.openai.com:443 ->|                              |
     |<- 200 Connection Established --|                              |
     |                                |                              |
     |== TLS handshake (leaf cert) ==>|                              |
     |   (client thinks it's talking  |                              |
     |    to api.openai.com)          |                              |
     |                                |                              |
     |-- GET /v1/models HTTP/1.1 ---->|                              |
     |   (plaintext inside proxy)     |-- TLS to real upstream ----->|
     |                                |   + injected Authorization   |
     |                                |<- response ------------------|
     |<- response --------------------|                              |
```

Steps:
1. Parse `CONNECT host:port` from HTTP request
2. Send `HTTP/1.1 200 Connection Established\r\n\r\n`
3. Call `root_ca.sign_leaf(host)` — gets/caches leaf cert for this host
4. Build `rustls::ServerConfig` with the leaf cert
5. Wrap client TCP stream in `tokio_rustls::TlsAcceptor`
6. Read decrypted HTTP request from client
7. (Task 5 injects headers here)
8. Open outbound `tokio_rustls::TlsConnector` to real `host:443`
   using `webpki-roots` trust store
9. Forward request upstream, relay response back to client
10. For streaming responses, use `tokio::io::copy_bidirectional` on the
    inner plaintext streams

**Edge cases:**
- HTTP/2 over TLS: initial implementation targets HTTP/1.1 only.
  HTTP/2 ALPN negotiation can be added later.
- Large request/response bodies: stream, don't buffer
- Connection reuse: each CONNECT creates a new tunnel; no keepalive
  pooling needed in v1

**Verification:** Integration test with `hyper` test server behind the proxy:
```rust

    // 1. Start local HTTPS echo server
    // 2. Start proxy with test CA
    // 3. Client sends CONNECT through proxy

}
```

### Task 5: Header injection via policy — M

**Files:**
- `crates/abox-proxyd/src/egress_proxy.rs` (the new handler from Task 4)

**Implementation:**

After parsing the inner HTTP request (step 6 of Task 4):
```rust
if let Ok(Some(rule)) = policy.evaluate_egress(&host) {
    match std::env::var(&rule.env_var) {
        Ok(value) => {
            let header_value = rule.header_template.replace("{value}", &value);
            request.headers_mut().insert(
                HeaderName::from_str(&rule.inject_header)?,
                HeaderValue::from_str(&header_value)?,
            );
            tracing::debug!(host = %host, header = %rule.inject_header, "injected credential");
        }
        Err(_) => {
            tracing::warn!(
                host = %host,
                env_var = %rule.env_var,
                "credential env var not set; forwarding without injection"
            );
        }
    }
}
```

**Note:** If the env var is unset, the request proceeds without injection.
This avoids breaking the agent's request — the upstream will return 401,
which is more debuggable than a proxy error.

**Existing policy rules** (`policies/default.toml:87-113`):

| Domain | Header | Env Var | Template |
|--------|--------|---------|----------|
| `api.anthropic.com` | `x-api-key` | `ANTHROPIC_API_KEY` | `{value}` |
| `api.openai.com` | `Authorization` | `OPENAI_API_KEY` | `Bearer {value}` |
| `*.googleapis.com` | `Authorization` | `GOOGLE_API_KEY` | `Bearer {value}` |
| `api.github.com` | `Authorization` | `GITHUB_TOKEN` | `Bearer {value}` |

### Step 3: Handle virtiofsd for restored VMs — M

**This is the trickiest part.** Snapshots save VM memory state but NOT
host-side virtiofsd processes. The restore path must start fresh virtiofsd
instances before resuming the VM.

**Key constraint:** The virtiofsd socket paths must match what the
snapshotted VM was configured with. Cloud Hypervisor's `--fs` arguments
bake socket paths into the VM configuration at snapshot time.

**Implementation:**
- When creating a snapshot (Step 1), record the virtiofsd socket paths in
  a metadata file alongside the snapshot: `~/.abox/templates/<name>/meta.json`
  ```json
  {
    "virtiofs_sockets": {
      "workspace": "vfs-<original-id>.sock",
      "meta": "vfs-meta-<original-id>.sock",
      "status": "vfs-status-<original-id>.sock"
    }
  }
  ```
- When restoring, start virtiofsd instances bound to those exact socket paths
  (in the new sandbox's runtime_dir — symlink or copy if path differs).
- **Alternative approach:** Use a fixed, template-scoped socket naming scheme
  so restored VMs always find their sockets at predictable paths.

**Verification:** Restored VM can `ls /workspace` and write to `/abox-status/`.

### Step 4: One-command installer — S

**Files:**
- Create `scripts/install.sh`

**Implementation:**
```bash
#!/usr/bin/env bash
set -euo pipefail

REPO="X-McKay/abox"
INSTALL_DIR="${ABOX_INSTALL_DIR:-$HOME/.abox/bin}"
VM_DIR="$HOME/.abox/vm"

ARCH="$(uname -m)"
case "$ARCH" in
    x86_64)  TARGET="x86_64-unknown-linux-gnu" ;;
    aarch64) TARGET="aarch64-unknown-linux-gnu" ;;
    *)       echo "Unsupported: $ARCH"; exit 1 ;;
esac

# Fetch latest release tag
VERSION=$(curl -fsSL "https://api.github.com/repos/$REPO/releases/latest" | grep tag_name | cut -d'"' -f4)

# Download binary + VM assets + checksums
curl -fsSL -o /tmp/abox "https://github.com/$REPO/releases/download/$VERSION/abox-$TARGET"
curl -fsSL -o /tmp/vm-assets.tar.gz "https://github.com/$REPO/releases/download/$VERSION/abox-vm-assets-$ARCH.tar.gz"
curl -fsSL -o /tmp/SHA256SUMS "https://github.com/$REPO/releases/download/$VERSION/SHA256SUMS"

# Verify checksums
cd /tmp && sha256sum -c SHA256SUMS --ignore-missing

# Install
mkdir -p "$INSTALL_DIR" "$VM_DIR"
install -m 755 /tmp/abox "$INSTALL_DIR/abox"
tar xzf /tmp/vm-assets.tar.gz -C "$VM_DIR"

echo "Installed abox $VERSION to $INSTALL_DIR/abox"
echo "VM assets at $VM_DIR"
echo "Add to PATH: export PATH=\"$INSTALL_DIR:\$PATH\""
```

**Verification:** Test in a clean Ubuntu container.
